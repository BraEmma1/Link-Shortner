# MongoDB Schema & Database Documentation

Vaultz Links stores its operational data in MongoDB. Mongoose schemas are used to define validation, field structures, indices, and relationships.

---

## 1. User Schema

Represents users whose accounts are synced from WordPress JWT authentications.

* **Collection Name**: `users`
* **Mongoose Model File**: `server/src/models/User.js`

### Schema Structure
| Field | Type | Required | Unique | Default | Validation / Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `wpUserId` | `Number` | **Yes** | **Yes** | *None* | WordPress database ID of the user. Also serves as primary lookup key for sync. |
| `name` | `String` | **Yes** | No | *None* | Display name. Min length: 2, Max length: 100. Trimmed. |
| `email` | `String` | **Yes** | **Yes** | *None* | User email. Must match email regex pattern, trimmed, and lowercased. |
| `role` | `String` | **Yes** | No | `'user'` | Role within the URL Shortener. Allowed values: `['admin', 'user']`. |
| `lastLogin` | `Date` | No | No | `null` | Tracks last time the user logged in/synchronized. |
| `createdAt` | `Date` | Auto | No | *Auto* | Automatically handled by schema `timestamps: true`. |
| `updatedAt` | `Date` | Auto | No | *Auto* | Automatically handled by schema `timestamps: true`. |

### Indexes
- `{ wpUserId: 1 }` (Unique, Primary Sync Key)
- `{ email: 1 }` (Unique, Lookup Key)

## 2. Link Schema

Defines shortened URLs, tracking their owner, clicks counter, slug configurations, and active status.

* **Collection Name**: `links`
* **Mongoose Model File**: `server/src/models/Link.js`

### Schema Structure
| Field | Type | Required | Unique | Default | Validation / Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `userId` | `ObjectId` | **Yes** | No | *None* | Refers to `User._id` of the owner. |
| `title` | `String` | No | No | `''` | Optional descriptive link label. Max length: 150. Trimmed. |
| `slug` | `String` | **Yes** | **Yes** | *None* | Unique URL tail. Min length: 2, Max length: 50, alphanumeric + hyphens + underscores. |
| `targetUrl` | `String` | **Yes** | No | *None* | Long destination URL. Validated by URL regex patterns. |
| `clicks` | `Number` | No | No | `0` | Click counter. Cannot be negative. |
| `status` | `String` | **Yes** | No | `'active'` | Redirect active state. Enum: `['active', 'inactive', 'expired']`. |
| `createdAt` | `Date` | Auto | No | *Auto* | Handled by schema `timestamps: true`. |
| `updatedAt` | `Date` | Auto | No | *Auto* | Handled by schema `timestamps: true`. |

### Indexes
- `{ slug: 1 }` (Unique, generated by `unique: true`)
- `{ userId: 1, createdAt: -1 }` (Compound Index, optimizes Dashboard Link List sorting)

## 3. Analytics Schema

Tracks click events on short links for reporting trends, countries, browsers, operating systems, and referrers.

* **Collection Name**: `analytics`
* **Mongoose Model File**: `server/src/models/Analytics.js`

### Schema Structure
| Field | Type | Required | Unique | Default | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `linkId` | `ObjectId` | **Yes** | No | *None* | Refers to the clicked `Link._id`. |
| `ipAddress` | `String` | No | No | `'Unknown'` | Visitor IP address, used to prevent geo duplicates. |
| `country` | `String` | No | No | `'Unknown'` | Extracted ISO country code from GeoIP lookups. |
| `browser` | `String` | No | No | `'Unknown'` | Extracted browser name from User Agent. |
| `device` | `String` | No | No | `'Unknown'` | Visitor device category (e.g. Mobile, Tablet, Desktop). |
| `os` | `String` | No | No | `'Unknown'` | Visitor Operating System name. |
| `referrer` | `String` | No | No | `'Direct'` | Referral URL source (defaults to Direct for empty referrers). |
| `clickedAt` | `Date` | No | No | `Date.now` | Click event timestamp (indexed for time-range analytics). |

### Indexes
- `{ linkId: 1, clickedAt: -1 }` (Compound, range queries for specific link click charts)
- `{ linkId: 1, country: 1 }` (Compound, speeds up country distribution aggregates)
- `{ linkId: 1, device: 1 }` (Compound, speeds up device distribution aggregates)
- `{ linkId: 1, browser: 1 }` (Compound, speeds up browser distribution aggregates)
- `{ linkId: 1, os: 1 }` (Compound, speeds up OS distribution aggregates)
- `{ linkId: 1, referrer: 1 }` (Compound, speeds up Traffic Sources aggregations)

## 4. QRCode Schema

Stores styling and rendering parameters for custom QR Code configurations generated for short links.

* **Collection Name**: `qrcodes`
* **Mongoose Model File**: `server/src/models/QRCode.js`

### Schema Structure
| Field | Type | Required | Unique | Default | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `linkId` | `ObjectId` | **Yes** | **Yes** | *None* | Refers to the corresponding `Link._id`. |
| `userId` | `ObjectId` | **Yes** | No | *None* | Refers to the `User._id` of the owner. |
| `foregroundColor`| `String` | No | No | `'#000000'`| Hex styling for QR foreground lines. |
| `backgroundColor`| `String` | No | No | `'#ffffff'`| Hex styling for QR background block. |
| `margin` | `Number` | No | No | `4` | Quite zone margin width of the QR code. |
| `errorCorrectionLevel`| `String` | No | No | `'M'` | Quality level for scan redundancy. Enum: `['L', 'M', 'Q', 'H']`. |
| `createdAt` | `Date` | Auto | No | *Auto* | Handled by schema `timestamps: true`. |
| `updatedAt` | `Date` | Auto | No | *Auto* | Handled by schema `timestamps: true`. |

### Indexes
- `{ linkId: 1 }` (Unique, maps one QR record to a link)
- `{ userId: 1 }` (Lookup index to fetch all user QR codes)
